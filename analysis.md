# Технический анализ логов SonicBook (13.04.2026)

На основе анализа логов `app_debug.log` и текущего поведения системы выявлены следующие области для улучшения и исправления.

---

## 1. Google Drive API (HTTP 400 Bad Request)
### Описание
Ошибка `httpx.HTTPStatusError: Client error '400 Bad Request' for url 'https://oauth2.googleapis.com/token'` возникает при попытке автоматического обновления (`refresh_token`) сессии.

### Причины
- Истечение срока действия `refresh_token` (в режиме "Testing" Google Cloud Console лимит составляет 7 дней).
- Отзыв прав доступа пользователем.

### Рекомендации
- **Для пользователя:** При возникновении ошибок загрузки или "вечного" ожидания списка файлов Drive, необходимо выполнить **Disconnect** (Отключить), а затем **Connect Google Drive** (Подключить) заново в настройках приложения. Это принудительно обновит авторизационные токены.
- **Для разработчика:** 
    - Проверить логику обработки истекших токенов в `google_drive_service.py`. 
    - **Улучшение UX:** В случае получения 400/401 ошибки от Google API, выводить пользователю понятное сообщение: *"Срок действия сессии Google Drive истек. Пожалуйста, отключите и снова подключите аккаунт в настройках"*.
    - Добавить в UI визуальный индикатор (например, красный восклицательный знак рядом с Google Drive в настройках), если фоновая проверка токена не удалась.
    - Если приложение в статусе "Testing", добавить в UI информационную плашку о том, что токены в этом режиме живут только 7 дней.

## 2. Конфликты блокировки файлов в yt-dlp
### Описание
`yt_dlp.utils.LockingUnsupportedError: File locking is not supported`
Эта ошибка специфична для Windows и некоторых файловых систем, где запрещена блокировка файлов (file locking).

### Гипотеза исправления
В файле `processor.py` при инициализации `YoutubeDL` добавить параметр:
```python
ydl_opts = {
    'noleavetempfile': True,
    'nocheckcertificates': True,
    'no_file_lock': True,  # Добавить этот флаг
    # ... остальные опции
}
```

## 3. Права доступа Playwright (WinError 5)
### Описание
`PermissionError: [WinError 5] Access is denied` при попытке `asyncio.create_subprocess_exec` для запуска Chromium.

### Причины
- Антивирус или Windows Defender блокирует запуск браузера из-под Python-процесса.
- Недостаточные права текущего пользователя в директории с установленными браузерами Playwright.

### Рекомендации
- Запустить приложение от имени администратора (для проверки).
- Добавить исключение в антивирус для пути к `ms-playwright`.
- Проверить корректность установки: `playwright install chromium`.

## 4. "Шторм" предупреждений в SSE (socket.send)
### Описание
Массовые `WARNING - socket.send() raised exception` засоряют логи при разрыве соединения клиентом.

### Причины
В `main.py` (эндпоинт `/api/progress/stream/{task_id}`) генератор продолжает попытки отправки данных после того, как браузер закрыл соединение.

### Гипотеза исправления
Обернуть отправку в `try/except` или использовать более надежный метод проверки состояния запроса:
```python
async def event_generator():
    try:
        while True:
            if await request.is_disconnected():
                break
            # ... логика получения данных ...
            yield f"data: {json.dumps(data)}\n\n"
            await asyncio.sleep(0.5)
    except (asyncio.CancelledError, Exception):
        logger.debug("SSE stream disconnected")
```

## 5. Избыточность логирования Playwright
### Описание
Лог забит сообщениями `Initializing persistent Playwright browser...`.

### Рекомендации
Убедиться, что браузер инициализируется один раз в `lifespan`, а не при каждом запросе (что уже заложено в архитектуре, но, судя по логам, иногда происходит повторно при сбоях).
